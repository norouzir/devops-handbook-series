# About This Book {-}

This book is the first volume of the DevOps Handbook Series. It teaches Docker the way DevOps engineers actually use it: as the daily workhorse for building, shipping, and running applications. It assumes you are comfortable with the Linux command line, basic networking concepts such as ports and DNS, and at least one scripting language. It does not assume any prior container experience. Every chapter moves deliberately from concept to command, and every chapter ends with a short lab that you are expected to type out on a real machine. Reading about Docker is pleasant; typing the commands is what makes the knowledge stick.

The book is organized in two parts so it can serve two reading modes at once. Part I, Docker Essentials, covers the vocabulary and the mechanics: the mental model, installation and configuration, the container lifecycle, images and registries, Dockerfiles, and modern builds with BuildKit and buildx. Part II, Docker in Production, is the working engineer's part: storage and volumes, container networking, multi-container applications with Compose, security, the orchestration landscape, observability, and CI/CD operations. The parts are sequential; nothing in Part II assumes material outside Part I and the earlier chapters of Part II itself. The scope was chosen with care, and it deliberately stops there: this is not a Kubernetes book, not a Linux kernel book, and not a programming book. Where a topic belongs to a neighboring discipline, the book tells you exactly where Docker ends and the next tool begins.

The content reflects the state of the ecosystem as of October 2026. Facts were checked against Docker Engine v29 and Docker Desktop 4.97, which means the containerd image store is treated as the default, Compose appears as the v2 CLI plugin, the classic builder is treated as history, and recently deprecated features such as legacy links and the Device Mapper storage driver are described only so that you can recognize them and move away from them. If you are running an older engine, most of the book still applies, but you should plan an upgrade first; Chapter 2 explains the version constraints.

Three conventions run through the book. Commands you type in a shell appear in monospaced blocks, prefixed with a dollar sign for an unprivileged shell and a hash for root. Inline technical terms such as `image`, `volume`, and `registry` are kept in English, matching how professionals speak. Finally, notes marked as Best practice summarize hard-won operational wisdom, while Watch out boxes flag the mistakes that most often cause incidents, from filled disks to leaked credentials. Work through the chapters in order the first time; afterwards, the appendices are designed to serve as a compact desk reference.

Every chapter closes with a *See also* list, every internal reference is a live link, and the Part dividers, table of contents, and headings are navigable in all three editions - in the PDF the contents carry computed page numbers and the heading tree appears in the outline panel.
