# About This Book

This book is the eighth volume of the DevOps Handbook Series. *Docker for DevOps Engineers* answered how to package an application, *Kubernetes for DevOps Engineers* answered how to run it, *GitHub Actions for DevOps Engineers* answered how to build, test, and ship it, *Ansible for DevOps Engineers* answered how to configure it, *Terraform for DevOps Engineers* answered how to describe the infrastructure underneath it in code, *Prometheus & Grafana for DevOps Engineers* answered how to measure it with metrics, and *Elastic Stack for DevOps Engineers* answered how to search its logs. This volume answers the question the earlier volumes have been quietly standing on: *where does all of this actually run?* Every container image the earlier books produced lands somewhere, every pipeline ships to some platform, every Grafana panel reads from some service - and for a majority of teams that somewhere is Amazon Web Services. What this book covers is the ground those volumes have been standing on: the account, the network, the machines, and the managed services that their images, pipelines, and dashboards ultimately land on.

The book is organized in two parts. Part I, AWS Foundations, builds the core services a platform team lives in every day: the global map of Regions and Availability Zones and the AWS CLI that drives them; IAM, the permission system that every other chapter quietly depends on; EC2, the virtual machines that remain the workhorse even in a Kubernetes age; VPC, the network you actually own; S3, the object store that has become a platform of its own; RDS, the managed databases that take the 3 a.m. pages away; EKS, the managed Kubernetes control plane; and Lambda, the serverless toolbox that solves a whole class of glue problems in a few dozen lines. Part II, Operating AWS at Scale, is the working team's part: CI/CD pipelines that deploy to AWS from GitHub Actions without long-lived credentials, observability with CloudWatch and its honest division of labor against the series' Prometheus and Grafana stack, Terraform practice specific to AWS - remote state, modules, AMI data sources, drift - and cost management, because an unattended AWS account is the most expensive to-do list you will ever own. The parts are sequential; Part II assumes only Part I and the earlier chapters of Part II itself.

The content reflects the platform as of October 2026. AWS does not ship versioned releases the way the tools in earlier volumes do; services evolve continuously, so the book pins the durable artifacts instead: the **AWS CLI v2** is the command line used throughout, **Amazon Linux 2023** is the AMI of choice for EC2 examples, **Graviton (arm64)** instances are the default price-performance recommendation, **IMDSv2** is assumed for instance metadata, and the **`aws-actions/configure-aws-credentials` GitHub Action v6** carries the OIDC-based CI story in Chapter 9, including the mid-2026 change that folds organization and repository identifiers into the token's `sub` claim. Where a number genuinely moves - Free Tier allowances, service quotas, Lambda runtime rotation, EKS Kubernetes minor versions - the book says what kind of number it is and points at the console or the docs page that owns it, rather than copying a figure that will age. Where a capability is region-gated, plan-gated, or pricing-model-dependent, the book says so explicitly instead of presenting the happy path as universal.

Three conventions run through the book. Commands, configuration, JSON, and policy documents appear in monospaced blocks, and every example is shown complete enough to paste into a shell with AWS CLI v2 configured and run - the running example is one small but realistic web platform, assembled piece by piece from Chapter 1 through the Part II pipeline. Technical terms such as Region, role, security group, subnet, and task are kept in English and capitalized when they name a platform concept, matching how professionals speak. Notes marked **Best practice** condense operational wisdom, while **Watch out** boxes flag the mistakes that cause the most production pain - the `0.0.0.0/0` security group rule, the forgotten NAT gateway, the log group with no retention, the final snapshot never taken. Because the book targets practitioners, full labs appear in the five chapters where hands-on practice changes the most: launching and snapshotting a real EC2 instance, building a two-tier VPC from scratch, standing up a versioned and life-cycled S3 bucket with a static site, deploying a workload to EKS with an ALB and a pod-level IAM role, and wiring an end-to-end GitHub Actions pipeline that deploys to EKS with OIDC and no stored credentials. The appendices compress the rest into a desk reference: an AWS CLI cheat sheet organized by service, a set of starter configurations you can copy into a repository, and a troubleshooting guide organized by symptom.

Every chapter closes with a *See also* list, every internal reference is a live link, and the Part dividers, table of contents, and headings are navigable in all three editions - in the PDF the contents carry computed page numbers and the heading tree appears in the outline panel.
