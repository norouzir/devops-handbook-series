# About This Book {-}

This book is the third volume of the DevOps Handbook Series. The first two volumes answered how to package an application and how to run it; this one answers how to build, test, verify, and ship it automatically, on every commit, without a human shuffling artifacts between laptops. GitHub Actions is the automation engine built into every GitHub repository, and for a growing majority of teams it has become the default place where software is assembled and released. Every chapter moves from concept to working YAML, and every mechanism is explained in terms of what it costs you in minutes, in blast radius, or in cognitive load.

The book is organized in two parts. Part I, GitHub Actions Essentials, covers the vocabulary and the mechanics: the execution model, workflow anatomy and triggers, jobs, steps, and runners, actions and the Marketplace, expressions and contexts, artifacts and caching, continuous integration with matrices and quality gates, and container builds with GitHub Packages. Part II, Advanced Operations, is the working platform team's part: continuous delivery with environments and approvals, reusable workflows and automation, self-hosted runners and the Actions Runner Controller, security hardening and supply-chain integrity, monitoring and cost management, and enterprise adoption including migration from Jenkins, GitLab CI, CircleCI, and Azure DevOps. The parts are sequential; nothing in Part II assumes material outside Part I and the earlier chapters of Part II itself.

The content reflects the platform as of October 2026, and the platform has been moving quickly. JavaScript actions now run on the Node 24 runtime: Node 24 became the default on June 16, 2026, and Node 20 was removed from runners on September 23, 2026, so actions pinned to old majors have started to fail loudly. Workflow dependency lockfiles went from public preview on October 14, 2026 to general availability on October 28, 2026, giving teams a way to pin action references to reviewed commits. Artifact attestations, OIDC federation with custom claims, and the Actions Runner Controller (release 0.15.0) are treated as settled practice, not novelty. Billing changed too: self-hosted runner usage on GitHub-hosted services began to be metered at 0.002 dollars per minute from March 1, 2026. Where a feature is a preview or differs by plan, the book says so explicitly rather than presenting the happy path as universal.

Three conventions run through the book. Commands and YAML appear in monospaced blocks, and workflow files are shown in full so you can paste them directly into `.github/workflows/`. Technical terms such as workflow, job, runner, and environment are kept in English and capitalized when they name a platform concept, matching how professionals speak. Notes marked as Best practice condense operational wisdom, while Watch out boxes flag the mistakes that cause the most incidents, from script injection through `github.event` values to surprise bills from uncapped matrix jobs. Because the book targets practitioners, full labs appear in the five chapters where hands-on practice changes the most: your first pipeline, matrix CI, environment-based deployment, runner infrastructure, and OIDC-secured deployments. The appendices compress the rest into a desk reference: a workflow syntax cheat sheet, four starter workflows you can adopt today, and a troubleshooting guide organized by symptom.

Every chapter closes with a *See also* list, every internal reference is a live link, and the Part dividers, table of contents, and headings are navigable in all three editions - in the PDF the contents carry computed page numbers and the heading tree appears in the outline panel.
