# About This Book

This book is the ninth volume of the DevOps Handbook Series. *Docker for DevOps Engineers* answered how to package an application, *Kubernetes for DevOps Engineers* answered how to run it, *GitHub Actions for DevOps Engineers* answered how to build, test, and ship it, *Ansible for DevOps Engineers* answered how to configure it, *Terraform for DevOps Engineers* answered how to describe the infrastructure underneath it in code, *Prometheus & Grafana for DevOps Engineers* answered how to measure it with metrics, *Elastic Stack for DevOps Engineers* answered how to search its logs, and *AWS for DevOps Engineers* answered where all of it runs on the platform most teams start on. This volume answers the natural follow-up: *what about the other two?* Microsoft Azure and Google Cloud are not niche platforms - they are where a large share of the industry's Kubernetes clusters, serverless workloads, and data platforms live - and for an engineer fluent in AWS they are best learned as a **delta**: the same concepts, different vocabulary, different defaults, and a handful of genuinely new ideas worth stealing.

The book is organized in two parts, and it is deliberately written for the AWS-native reader. Part I, Microsoft Azure, builds the platform the way an Azure team meets it: the tenant-subscription-resource group hierarchy and the az CLI that drives it; Microsoft Entra ID with Azure RBAC and managed identities, the permission system every later chapter quietly depends on; virtual machines and Bicep, Azure's answer to infrastructure as code; VNets, NSGs, Blob storage, and Azure Database for PostgreSQL; AKS, the managed Kubernetes control plane; Azure Functions and Container Apps, the serverless toolbox; and a CI/CD chapter that deploys to Azure from GitHub Actions with OIDC federation and no stored credentials. Part II, Google Cloud and Multi-Cloud Delivery, repeats the journey on GCP - projects and gcloud, IAM with Workload Identity Federation, VPC and Compute Engine with managed instance groups, Cloud Storage and Cloud SQL, GKE with Autopilot, Cloud Run, and a keyless pipeline - and then closes with the part the other books could not deliver: a capstone that ships the same application to AWS, Azure, and GCP, compares the platforms with the bills attached, and a decision framework for when multi-cloud is a strategy and when it is an expensive habit. The parts are sequential; Part II assumes Part I, and the capstone assumes both.

The content reflects the platforms as of October 2026. Like AWS, neither cloud ships versioned releases the way the tools in earlier volumes do, so the book pins the durable artifacts instead: the **az CLI 2.x with its bundled Bicep CLI** is the Azure toolchain throughout, **`azure/login` v3** and **`google-github-actions/auth` v3** with **`actions/checkout` v7** carry the OIDC CI story, **AKS** follows the standard Kubernetes N-2 support policy, **GKE Autopilot** is the book's default GKE mode, **Cloud Run** is covered in its request-based, revision-splitting form, and **Artifact Registry** is assumed as the only GCP container registry (Container Registry is gone). Names matter and have stabilized: Azure AD has been **Microsoft Entra ID** since 2023, and the book uses the new names. The mid-2026 change to GitHub's OIDC `sub` claim - the one *AWS for DevOps Engineers* documented for `configure-aws-credentials` v6 - affected all three clouds identically, so the Azure and GCP federation chapters each show the trust configuration that accounts for it. Where a number genuinely moves - free credits, service quotas, per-minute prices, runtime versions - the book says what kind of number it is and points at the console or pricing page that owns it, rather than copying a figure that will age.

Three conventions run through the book. Commands, configuration, Bicep, and YAML appear in monospaced blocks, and every example is shown complete enough to paste into a shell with the `az` or `gcloud` CLI configured and run - the running example is the same small web platform, **shopnow**, that the series has grown since the Docker book, here re-homed onto both clouds piece by piece. Azure examples default to the `westeurope` region and GCP examples to `europe-west3`, so the series' examples sit next to each other in central Europe. Technical terms such as tenant, resource group, service account, revision, and zone are kept in English and capitalized when they name a platform concept. Notes marked **Best practice** condense operational wisdom, while **Watch out** boxes flag the mistakes that cause the most production pain - the recursive resource group delete, the `Contributor` role that still cannot read a blob, the basic Editor role, the Cloud SQL instance with a public IP, the Cloud Run deployment that melts its database. Because the book targets practitioners, full labs appear in the six chapters where hands-on practice changes the most: writing and deploying a Bicep stack you can break and rebuild, standing up AKS with workload identity federation, wiring a keyless GitHub Actions pipeline to Azure, bringing up a GKE Autopilot cluster with identity-aware pods, deploying to Cloud Run with a canary and a rollback, and the Part II capstone that puts the same application on all three clouds and reads the bills. The appendices compress the rest into a desk reference: a service map from AWS through Azure to GCP, an `az` and `gcloud` cheat sheet organized by service, starter configurations you can copy into a repository, and a troubleshooting guide organized by symptom.

Every chapter closes with a *See also* list, every internal reference is a live link, and the Part dividers, table of contents, and headings are navigable in all three editions - in the PDF the contents carry computed page numbers and the heading tree appears in the outline panel.
