# About This Book

This book is the fifth volume of the DevOps Handbook Series. *Docker for DevOps Engineers* answered how to package an application, *Kubernetes for DevOps Engineers* answered how to run it, *GitHub Actions for DevOps Engineers* answered how to build, test, and ship it automatically, and *Ansible for DevOps Engineers* answered how to configure and operate what is running. The question that follows is where the infrastructure itself comes from: Who creates the networks, clusters, databases, load balancers, and DNS records in the first place, and how do you change them on a Tuesday afternoon without a wiki page, a ticket queue, and a tribal memory of what was hand-modified in the console three years ago? Terraform is the industry's default answer to that question, and this book is a working engineer's guide to using it well - from your first `plan` to infrastructure estates measured in thousands of resources.

The book is organized in two parts. Part I, Terraform Essentials, builds the vocabulary and the muscle memory: the Infrastructure as Code model and how Terraform's plan-based workflow differs from scripts and from Ansible's imperative-adjacent model, installation and your first real project, the HCL language from blocks and expressions to `for` and `dynamic`, providers and the Registry, the resource/data source/variable/Output quartet that makes up every configuration, the core `init`-`plan`-`apply` workflow, state management including remote backends and locking, and modules as the unit of reuse. Part II, Production Terraform, is the working platform team's part: multiple environments and the workspaces-versus-directories decision, secrets and the uncomfortable truth about state files, testing with `terraform test` and policy enforcement with Terraform Policy and OPA, CI/CD pipelines that treat infrastructure like software, HCP Terraform and Stacks for team collaboration, and the production patterns - drift detection, zero-downtime replacement, refactoring with `moved` blocks - that keep large estates honest. The parts are sequential; Part II assumes only Part I and the earlier chapters of Part II itself.

The content reflects the platform as of October 2026. The current stable release is Terraform 1.17.0 (October 21, 2026), whose headline changes this book incorporates: Terraform Policy is now generally available and `-policies` is a first-class flag on `plan`, `apply`, and `query`; provider requirements can now be parameterized with variables and locals; and `-minimal-refresh` makes plan-time refresh cheaper for large estates. Two structural facts of the 2020s shape the examples throughout. First, since HashiCorp moved Terraform to the Business Source License in 2023, the ecosystem has two siblings: HashiCorp's Terraform and the Linux Foundation's OpenTofu (MPL-2.0, CNCF-hosted, currently at 1.13), and the book treats both as facts of life - the HCL you write works on both, while the surrounding products (HCP Terraform, Stacks, Sentinel) differ. Second, the platform grew real engineering tools: ephemeral resources and write-only arguments changed how secrets flow (Terraform 1.10+), the S3 backend gained native lockfile-based locking, `terraform test` and provider mocks matured into a usable test framework, and the `action` block brought provider operations into the workflow. Where a capability is HCP-Terraform-only, experimental, or provider-dependent, the book says so explicitly instead of presenting the happy path as universal.

Three conventions run through the book. Commands and HCL appear in monospaced blocks, and every configuration is shown complete enough to paste into a project and run against disposable targets - the labs use the Docker provider so that the "cloud" costs nothing and cannot page anyone. Technical terms such as provider, module, workspace, and execution are kept in English and capitalized when they name a platform concept, matching how professionals speak. Notes marked **Best practice** condense operational wisdom, while **Watch out** boxes flag the mistakes that cause the most incidents: applying a plan generated against the wrong workspace, editing a lock file by hand, treating `state rm` as a delete button, or trusting that "sensitive" makes an output secret. Because the book targets practitioners, full labs appear in five chapters where hands-on practice changes the most: your first real project against container targets, a complete plan/apply/destroy cycle with saved plan files, state surgery with import and `moved`, a reusable module built and consumed twice, and a GitHub Actions pipeline that plans on pull requests and applies on merge. The appendices compress the rest into a desk reference: a CLI and workflow cheat sheet, an HCL functions cookbook, and an ecosystem-and-troubleshooting guide organized by symptom.

Every chapter closes with a *See also* list, every internal reference is a live link, and the Part dividers, table of contents, and headings are navigable in all three editions - in the PDF the contents carry computed page numbers and the heading tree appears in the outline panel.
